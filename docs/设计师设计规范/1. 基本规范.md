# 1\. 基本规范

## 设计稿基础规范

### 文档必须遵守:

- D2C设计稿中不得混入探索稿、废弃稿、参考和多个未标明的新旧版本；

- 一个交付对象只保留一个有效frame；

- Frame名应有效且唯一，例如“首页1”，名称不能重复或空白；

- 画布旁的说明图层必须加 x\-，或置于 D2C Frame 之外。

### 画框Frame基础设置：

- 每个 D2C Frame 只表达一个页面、弹窗或可独立生成的模块；

- frame必须勾选【裁切内容/Clip】；

- 删除隐藏的废弃图层、空 Group、重复背景和无作用蒙版、参考线；

- 不能使用超大透明矩形、空白矩形或不可见图层制造边距；

- 页面高度应由内容和 Auto Layout 决定；

- 仅在固定浮窗、弹窗、滚动容器等有真实约束的场景使用固定高度。

### 图层命名规范：

- 命名前缀根据【D2C打标规范】来编辑，前缀和后缀等间隔连字符使用“\-”；

- 使用英文，可用自然语义的拼音；

- 同一父级下尽量不要出现同名节点，重复项使用真实语义或稳定序号；

### Group分组逻辑（参与自动布局后是Frame）：

- 每个独立卡片使用一个 Group 编组，避免过多层级嵌套。

- 删除空 Group 及无实际用途的 Group，保持结构简洁。

- 对超出预期边界的内容，使用矩形蒙版约束，确保 Group 边界准确。

- Group 边界应贴合实际内容，不得包含无意义的透明像素（padding）。特殊场景下，如需为切图容器预留空间，可使用透明矩形占位。

### 文字与内容：

- 所有业务文本保持为 Text 图层;除 Logo 或明确切图场景外，不轮廓化、不栅格化。

- 只允许使用携程品牌有版权的字体、字重与行高，并伴随设计稿同步给开发同事。

- 文本框宽度和高度行为与真实内容一致，避免固定高度导致换行后裁切。

- 列表、卡片、按钮的文本框使用【填充容器】，至少用短文案、长文案和空值各验证一次。
