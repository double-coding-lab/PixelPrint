# D2C 执行与增量验收契约

本契约由 H5、RN、局部修复和换肤共用；先按本轮意图选路径，再执行各 Skill 对应步骤。代码、节点事实、真实工具结果和用户要求是判断依据。生成器的前缀、单位、adapter 与现有检查器门禁继续适用。

## 1. 本轮任务先分流

| 本轮意图 | 读取和执行范围 |
| --- | --- |
| 首次生成、整页结构重做 | 完整设计缓存、素材准备、Rule-Scan、区块实现、合并及真实验收 |
| 继续未完成任务 | 先读 `.d2c-tasks.md`、已保存文件、报告及素材清单，核对输入后只补未完成或已失效部分 |
| 点击、滑动、滚动、状态或一处样式修改 | 先定位当前入口和源码，列出本轮行为与外观约束，最小修改后检查受影响范围 |
| 仅替换图片和颜色 | 固定结构、尺寸、文案和交互，复用有效报告；按实际素材差异补切和映射，不重做整页 |

多个区块受同一交互影响时，列出共同状态、依赖与唯一写入 owner，做有边界的联动修改。区块数量本身不触发整页重做。用户显式要求整页重构时才切回完整生成。

本轮不需要新设计事实时，不为“确认一下”重新请求 Figma、不要求重新授权已有输出目录、不重新做 Rule-Scan。需要新节点、用户换稿、缓存缺失/不完整或设计版本变化时，才执行对应设计步骤；未复验整页时不能声称整页规则和视觉均通过。

## 2. 输出目录与写入范围

首次生成没有用户指定子目录时，代码默认放 `config.output.dir/home/`；新 H5/RN 配置的根目录均为 `pages/`，即 `pages/home/index.jsx` 或 `index.tsx`。区块放页面内的 `blocks/<英文别名>/`，不能写到 `pages/blocks/`。默认切图slug仍独立使用page，或沿用已锁定主题slug；图片按images.assetsDir、真实切图回执与清单确定，不从代码home推导图片目录或地址。

已有页面沿用实际入口、import 和组件组织；自定义根目录保留。目录已存在且无法确认属于本次继续/修改目标时，沿主 Skill 的目录三态守卫处理，不能覆盖无关业务代码。目录授权不等于任意删除或搬迁权限。

## 3. 共用设计缓存与扫描结果

- 首次设计读取或设计输入变化时，主 agent 按实际 CLI 的 `cache-check` 校验一次，再取得目标完整根节点缓存。完整性需核对脚本返回的深度、截断信息与实际节点范围，浅层结果不能当作完整缓存。
- 结构识别、Rule-Scan 和 UI 实现消费同一 fileKey/rootNodeId 的有效完整缓存。子任务只读缓存，不各自重复 `cache-check`，不逐个小节点串行请求网络；确实缺失时由主 agent 合并需要补取的范围。
- 大节点返回保存到真实缓存/临时文件，先整理节点范围、计数、所需属性及文件定位，不反复把整棵树或完整代码塞进对话。按目标读取事实仍须有完整来源，不能用短摘要冒充完整扫描。
- 同一上下文中的 Skill、规则文档和已知节点资料读取一次后复用；只有缺口、内容变化或独立子上下文确需该资料时再读。路径从实际目录和 `rules/README.md` 取得，不猜 `R01.md` 等不存在的文件名。
- 同页面/同主题补切沿用其已有素材目录，主题在上层目录隔离；不同主题相同位置尽量使用相同英文语义文件名，同批重名保留稳定后缀。文件名、路径和摘要以真实清单/工具回执为准，改名时同步引用与清单，不能猜测 URL。
- 确定性属性按现有脚本与缓存事实整理；模型判断语义、设计意图和未知项。线下未提供的服务端扫描工具不能假装已经运行，机械命中与最终代码检查也不能互相替代。
- 首次 Rule-Scan 仍覆盖目标范围和主 Skill 规定的规则。已有匹配版本的报告可复用；代码修改不自动使设计事实失效，节点、配置、前缀协议或规则版本变化则定点重扫受影响范围。

扫描按少量规则或明确子树分批保存工作结果，立即在 `.d2c-tasks.md` 记录已完成范围、输入定位、临时批次文件和下一步。完整 `rule-hits.json` 只有核对全部目标后才交给 UI 消费；未完成批次不能写空 hits 冒充完整报告。最终仍用现有 schema，按 rule、nodeId 和现有触发证据去重合并，不凭算法猜未判断的语义项。

## 4. 主子任务并行与失败交接

- 主 agent 委派独立区块后，继续自己的区域及入口骨架；为在途区块预留接口和占位。需要依赖产物、开始组合、整页预览或交付前才等待相应子任务，不能派完就停工。
- 扫描任务写自己的报告，实现 owner 写自己的源码和 QA；共享入口、根样式、配置、总清单由主 agent 单独写。检查使用目标真实 nodeId/root 和文件范围，不把整个父级目录交给子任务当授权范围。
- UI owner 保存源码后，实际执行本区块的 `check-rules --block <实际区块目录> --cache-key <fileKey> --root <真实nodeId>` 并修复违规；不能扩大到父目录或代替最终merge。扫描任务只交报告，不把自己当作UI自验者。报告绑定源码/配置/缓存摘要，写入后旧通过立即失效。
- 源码交付、规则检查和视觉验证分别记录；源码完整且必要区块规则通过可交给主任务组合，缺少预览时视觉保持未验证。主任务核对交付并最终merge，不重新语义扫描已有效通过的子块；当前merge工具仍按整页执行，不能声称有跳过子块的参数。
- 每个阶段保存已完成文件、输入版本、待处理问题与下一步。子任务失败也要交回实际文件、已完成报告和具体失败步骤；父任务先核验已保存结果，再接手或缩小范围重派，不因失败丢弃整块进度。
- 宿主能恢复同一子任务上下文时优先接续；不能恢复时用落盘事实重建，明确上下文缺口。缺少可靠结果的写入、上传先核验是否已发生，不能盲目重放。

## 5. 先保存，再验证最终版本

每次检查前保存完整的相关源码和样式，用宿主真实修订或文件摘要绑定入口、配置、设计基准、依赖、素材、视口和动作计划。无修订服务时可记录本地内容摘要，不虚构平台接口。检查期间保持被检查输入只读；任一关联输入变化后，受影响证据作废并重新排在保存之后执行。

先前针对旧版本、残缺候选或同批写入前的检查不扣一次有效验收机会，也不能作为新版本通过的证据。候选目录检查成功后，实际替换仍需核对最终 diff 和必要的最终版本检查；不要求用户再发一次“继续”才做这一步。

局部交互任务默认一轮有效验收，必要时最多再作两轮有具体证据的修正复验；同一问题无改善时停止重复猜改，转查映射、事件、样式命中、状态、单位或报告适用范围。计数按目标和最后已验输入记录在 `.d2c-tasks.md`，普通“继续”沿用；用户新增需求或确实更换输入时记录原因后重定范围。达到上限仍未通过时保存产物、明确缺口与下一步，不伪造完成或降低原有硬门禁。首次生成的规则检查照原 Skill 完整执行。

## 6. 交互修改的保形与行为验收

1. 修改前，在实际可运行且有截图能力时保存当前页面的真实基线，记录入口、视口、滚动位置、选中项及稳定外观；既有页面以修改前页面为保形基线，Figma 用来补设计事实。
2. 将用户要求拆成可观测目标。例如循环标签要求点击谁谁居中、一次按住拖动经过多个标签时依次切换、首尾双向回环，就逐项保留目标；不能只验证松手后的最终选中态。
3. 用宿主实际提供的浏览器/原生自动化定位真实元素，执行点击、滑动、滚动并读取选中态、位置、文本或属性。明确涉及快速连续操作、反向拖动或边界时，也验证相应竞态与边界。截图或静态读代码不能证明行为发生。
4. 修改后在相同视口、滚动和等价选中态截图，与修改前基线比较受影响区域及接缝；除用户明确允许的变化，间距、尺寸、字体、色彩和背景保持。交互产生的正常状态差异与布局回归分别判断，动态图片也不能当作无关区域已比对。
5. 发现样式回归先定位并修复非必要改动，不为通过行为断言重写整个布局。RN Web 只能证明浏览器兼容表现，原生触摸和原生组件仍需对应环境验收。

没有浏览器、原生设备或图片读取能力时，继续完成可验证的源码和规则检查，明确列出“交互/视觉未验证”及原因；不能编造动作成功、截图、断言或节点坐标。

## 7. 进度、工具纠错与交付

- 开始执行时向用户简述当前阶段和下一步；设计/素材就绪、开始写代码、编译/验收、遇到阻塞和完成时更新实际进度。运行中只依据真实结果说明，不能长期只有工具调用，也不输出无法确认的百分比。
- 工具参数错误先读实际定义及固定错误信息，修正字段、类型、路径或范围再调用；不原样无限重试。网络瞬时故障遵守客户端重试和等待要求，权限、Token、存储、磁盘与环境故障按实际原因报告，不伪装成布局违规。
- 最终答复前核对目标入口、样式与依赖都已实际保存；入口仍为空壳或缺少导入依赖时补齐缺失部分，最多两次仍无进展就交回真实缺口，不能只有解释而不落代码。
- 文件已保存、编译成功、规则通过、视觉通过和交互通过分别报告。最终答复对应用户本轮要求，列出实际改动、有效验证和未完成项；不能以“接下来我会实现”结束并宣称交付完成。
- 交付前核对最初目标和最终版本。只要已满足且必要检查通过就收尾，不无限截图、重读资料或追加用户未要求的重构。截图与报告清理前保留真实可读定位，复制或保存失败时保留原件。

## 8. 线下能力边界

宿主 Agent 的对话恢复能力和磁盘文件可用于继续工作；本契约不引入服务端的数据库、租约、检查点、自动失败重排、对象存储、Token 管理或 `inspect_preview` 等平台专用工具。仅在宿主确实提供相应能力时按其真实契约调用。规则同步不代表这些服务端能力已在线下实现。
